# Writing standard

This repository uses a writing style that follows the rules of ASD-STE100 Simplified Technical English (STE).

## Limit of this standard

The text follows the STE writing rules. It is not certified.
No one checked the text against the official STE dictionary with the official tools.
Do not describe this repository as "STE compliant" or "STE certified".

## Rules

1. Write sentences of 20 words or fewer for procedures and 25 words or fewer for descriptions.
2. Write one topic in each sentence.
3. Use the active voice. Write "The script deletes the file", not "The file is deleted".
4. Use one word for one meaning. Use the terms in `GLOSSARY.md`.
5. Use a verb in the imperative form for each instruction step.
6. Use articles ("the", "a") and do not drop them.
7. Do not use phrasal verbs, idioms, or figurative language.
8. Use the simple tenses. Use the simple present for facts and the simple past for events.
9. Use numerals for measurements and always write the unit. Put a space between the number and the unit, as in "8 GiB".
10. Put a warning before the step it applies to.

## Technical names

Names of tools, commands, files, and metrics are technical names. Do not change them to make them simple.
Write each technical name exactly as the tool writes it, in a code span where the name is a command or a file.

## Scope

These rules apply to all prose in `README.md`, `GLOSSARY.md`, `docs/`, issue text, and pull request text.
They do not apply to code, to code comments, or to the Conventional Commits prefix of a commit message.
